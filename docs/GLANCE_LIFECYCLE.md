# Glance lifecycle and quiet-work contract

`EryloGlance` is an opt-in Swift package foundation. The application mounts only its Battery and Volume system providers (plus the separately owned Countdown-based Focus Timer); Calendar remains unmounted. Construction is inert, each provider starts only after `enable()`, and `disable()` returns only after its observers, bounded consumers, one-shot boundaries, in-flight broker mutations, final activity cancellation, and ownership release have drained. Cancelled broker expiry tasks remain accounted for until they physically finish, so reset and terminal shutdown join even a cancellation-ignoring scheduler instead of reporting false idle state, regardless of whether broker shutdown or provider cleanup enters first. Shutdown cleanup runs independently of caller cancellation. Repeated and overlapping enable/disable calls share lifecycle tails rather than installing duplicate work. Calendar and Countdown also own generation-tokened deinitialization fallbacks: dropping the last enabled-provider reference finishes the Calendar relay, cancels owned tasks and one-shots, stops Calendar observation, drains captured broker mutations, and conditionally clears only a record bound to that instance's broker-issued ownership generation without retaining or re-entering the provider actor. A completed explicit disable consumes the token, so deinitialization cannot duplicate that cleanup.

Calendar and Countdown synchronously prepare a non-forgeable, per-identity claim intent before crossing an asynchronous broker or wrapper boundary. The shared coordinator orders those intents at their call sites, and disable/deinitialization synchronously retires an intent that has not reached the broker. A delayed predecessor can therefore never become newest after a successor, even when the successor has already released. An admitted successor claim atomically clears any predecessor record and installs a strictly newer broker generation in one actor turn. Submissions require an active current lease; retirement closes submission admission synchronously before asynchronous drain begins. Owned cancellation requires both the current generation and a record tagged with that generation, and terminal release prunes the generation. This fences a predecessor submit that has not yet entered the broker, a delayed cleanup that runs after successor publication, and an unavailable successor that cannot publish after takeover. Public unleased submission or cancellation atomically invalidates any provider generation and pending claim order for the same identity, so later provider disable or deinitialization cannot erase the unleased replacement. Owned expiry also prunes its admission generation. Retained identity lanes are capped at `ActivityLimits.maximumOwnershipCount` (128), pending intents are capped globally at `ActivityLimits.maximumOwnershipIntentCount` (256), and both counts are exposed in broker work state. Settled claims, retired intents, and released leases explicitly prune their state so capacity is reusable without an unbounded tombstone table.

The original public `GlanceActivityBroker` contract still requires only `submit(_:)` and `cancel(_:)`. `GlanceOwnershipActivityBroker` and `GlanceRevisionActivityBroker` are opt-in refinements. Production `ActivityBroker` implements both exact capabilities, while an existing external conformer continues through its original submit/cancel behavior instead of silently degrading to `.brokerRejected`. A revision-capable custom broker gets atomic legacy cleanup; an original-shape broker retains its prior unconditional cleanup semantics. Cross-instance replacement fencing is therefore guaranteed for ownership-capable brokers, including production, but cannot be retrofitted into an unchanged legacy implementation.

## Permission acquisition

`CalendarGlanceProvider.enable()` never requests EventKit access. This is the restore/start seam used for persisted enabled intent: `.notDetermined` produces an enabled, idle status with capability `.permissionRequired` and health `.healthy`, because the prompt-free provider machinery is functioning normally while it waits for a contextual user action. It owns no observer, query, boundary, or prompt.

A contextual user action may call `requestFullAccess()`. Permission acquisition is explicit and separate from provider start; after a grant, the caller invokes `enable()` again to start or resume observation. Concurrent contextual calls share one request, and disable drains a request already in flight. Denied, restricted, required, and failed states are closed values and never retain external error text.

## Presentation policy

The surface should be absent when no relevant activity exists:

- Battery treats the first ordinary snapshot as a quiet baseline. Later ordinary changes are transient for 1.8 seconds through the broker's cancellable one-shot expiry. An unplugged battery at or below 20% is ambient until the condition changes or the provider is disabled. Enabling alone never creates a battery activity.
- Calendar queries the next non-all-day, non-cancelled event within the bounded look-ahead, but presents it only from ten minutes before its start through its end. A distant meeting creates no broker activity and owns only one suspended lead-time boundary. Lead, start, and end transitions each use a single successor one-shot.
- Timer submits immutable timestamp-derived state once when activated and retains only its expiry one-shot. `setPresentationDemand(.visible)` records visibility but performs no broker mutation and replaces no boundary; `MM:SS`/`H:MM:SS`, progress, and the root VoiceOver value share one visible-only SwiftUI `TimelineView` snapshot. Timer visual descendants are accessibility-hidden so stale request detail cannot conflict with that live value. The native panel unmounts that rendered subtree when it is ordered out for sleep, policy, or shutdown, and logical hiding also removes the timeline; reshowing derives the current value directly from the original timestamps. A visible second therefore cannot allocate an activity revision, invalidate the cancel identity, or interrupt an in-flight cancel action. Natural expiry replaces Cancel with one routed **Done** action on an eight-second **Focus complete** acknowledgement and promotes a compact surface to a readable bounded peek whose notched body remains at least 40 points below the camera housing. The app runtime invokes one injected main-actor notifier, and production uses the standard macOS alert sound without a permission prompt. The provider becomes logically disabled immediately, while its accounted cleanup tail retains shutdown-barrier ownership until lease release and the runtime callback have both physically settled. Explicit cancellation and replacement invalidate the expiry generation and never publish completion. The brief does not justify a display link, provider ticker, or subsecond animation, so none is used.
- Volume treats the first synchronous default-output snapshot on every enable as a quiet baseline. Later snapshots are classified as level changed, muted, unmuted, or output changed and use one transient 1.8-second event-driven acknowledgement. Level is a percentage, mute is **Muted** rather than a false zero percent, unmute is **Sound on**, and output change uses a sanitized 96-byte public-CoreAudio display name or **Audio output**. The optional name remains transient inside Glance and is never persisted, logged, diagnosed, or exported. Initial source unavailability preserves enabled intent and one recovery observer while reporting honest unavailable health. Activation handoff delivers a callback captured during baseline settlement before admitting a newer live callback.

The new battery and meeting-window initializers report validation through `BatteryPresentationPolicyError` and `CalendarPresentationWindowError`. They do not add cases to the pre-existing `GlanceConfigurationError`, preserving exhaustive switches in existing clients.

Calendar observation includes EventKit store changes, system clock changes, time-zone changes, and wake. These events re-query and converge the current presentation and its one-shot boundary; there is no idle polling. Its bounded relay coalesces equivalent pending triggers but never lets a store change weaken a pending clock, time-zone, or wake trigger, because system triggers must force both presentation and boundary replacement. Broker submissions and cancellations run through one cancellation-insensitive mutation tail, so an older noncooperative call cannot land after a newer broker intent. A current nil, distant, or failed-query result always enqueues a clear intent behind any older mutation, even when no presentation has yet been recorded in provider state. `ActivityBroker` performs ownership comparison and mutation within one synchronous actor-isolated operation. Its refined-protocol witnesses enter the actor once and delegate without an intervening suspension. Other event streams use newest-only bounded buffering, and provider generation/revision checks make late callbacks inert.

## Verification and remaining gaps

`EryloGlanceTests` deterministically covers prompt-free persisted restore, explicit permission requests, quiet Battery, initial and re-enabled Volume, bounded output-name sanitation/fallback, semantic level/mute/unmute/output classification, distant-calendar baselines, ordered pending-to-live callback handoff, Battery unavailable/wake-style recovery, bounded acknowledgements, default-output unavailable recovery with one transient expiry, lead/start/end boundaries, clock/time-zone/wake convergence, event coalescing and mutation ordering, provider replacement fencing, lifecycle races, cancellation-insensitive drain, reusable capacity, and zero broker work from stale callbacks after disable. `EryloSurfaceTests` covers timestamp projection, physical and logical visibility retirement, closed launcher presets, activity-specific interaction eligibility, hover-update exit restoration, exact expanded-revision retirement, semantic progress lines, completion dismissal, notch geometry, semantic Volume symbols/copy, non-duplicative VoiceOver summaries, production-faithful previews, and native notched/notchless renders. `EryloAppRuntimeTests` proves a priority-only Volume handoff preserves and restores the exact Focus Timer revision/action with no timer churn and a still-valid Cancel, along with the one-shot completion notifier, routed Done dismissal, initial-unavailable settlement, retired-expiry cleanup across reset/disable/shutdown, Focus completion, replacement fencing, and shutdown barriers. `EryloActivityTests` covers ownership capacity, pruning and reuse, record-generation binding, public submission/cancellation fencing, and expiry invalidation. Debug and release builds run with warnings treated as errors through the publication evidence recorded on the pull request.

The application mounts Battery and Volume through narrow Trust lifecycle adapters
and the same `ActivityBroker` used by the Countdown Focus Timer and surface. A
persisted enable restores at startup without requesting access; Settings browsing
remains inert. Calendar, media, File Hold, and local integrations remain unmounted.
Real IOPowerSources delivery, CoreAudio volume/mute and device switching, macOS
sleep/wake timing, and settled energy use still require a signed app bundle, real
hardware, and Instruments. EventKit accounts, prompts, wall-clock, and time-zone
notifications remain separate Calendar foundation gates. Third-party brokers
that need cross-instance Calendar/Countdown fencing must adopt
`GlanceOwnershipActivityBroker`; the original two-method contract intentionally
preserves its historical runtime semantics.
