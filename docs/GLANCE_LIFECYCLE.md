# Glance lifecycle and quiet-work contract

`EryloGlance` remains an unmounted Swift package foundation. Construction is inert, each provider starts only after `enable()`, and `disable()` returns only after its observers, bounded consumers, one-shot boundaries, in-flight broker mutations, final activity cancellation, and ownership release have drained. Shutdown cleanup runs independently of caller cancellation. Repeated and overlapping enable/disable calls share lifecycle tails rather than installing duplicate work. Calendar and Countdown also own generation-tokened deinitialization fallbacks: dropping the last enabled-provider reference finishes the Calendar relay, cancels owned tasks and one-shots, stops Calendar observation, drains captured broker mutations, and conditionally clears only a record bound to that instance's broker-issued ownership generation without retaining or re-entering the provider actor. A completed explicit disable consumes the token, so deinitialization cannot duplicate that cleanup.

Calendar and Countdown synchronously prepare a non-forgeable, per-identity claim intent before crossing an asynchronous broker or wrapper boundary. The shared coordinator orders those intents at their call sites, and disable/deinitialization synchronously retires an intent that has not reached the broker. A delayed predecessor can therefore never become newest after a successor, even when the successor has already released. An admitted successor claim atomically clears any predecessor record and installs a strictly newer broker generation in one actor turn. Submissions require an active current lease; retirement closes submission admission synchronously before asynchronous drain begins. Owned cancellation requires both the current generation and a record tagged with that generation, and terminal release prunes the generation. This fences a predecessor submit that has not yet entered the broker, a delayed cleanup that runs after successor publication, and an unavailable successor that cannot publish after takeover. Public unleased submission or cancellation atomically invalidates any provider generation and pending claim order for the same identity, so later provider disable or deinitialization cannot erase the unleased replacement. Owned expiry also prunes its admission generation. Retained identity lanes are capped at `ActivityLimits.maximumOwnershipCount` (128), pending intents are capped globally at `ActivityLimits.maximumOwnershipIntentCount` (256), and both counts are exposed in broker work state. Settled claims, retired intents, and released leases explicitly prune their state so capacity is reusable without an unbounded tombstone table.

The original public `GlanceActivityBroker` contract still requires only `submit(_:)` and `cancel(_:)`. `GlanceOwnershipActivityBroker` and `GlanceRevisionActivityBroker` are opt-in refinements. Production `ActivityBroker` implements both exact capabilities, while an existing external conformer continues through its original submit/cancel behavior instead of silently degrading to `.brokerRejected`. A revision-capable custom broker gets atomic legacy cleanup; an original-shape broker retains its prior unconditional cleanup semantics. Cross-instance replacement fencing is therefore guaranteed for ownership-capable brokers, including production, but cannot be retrofitted into an unchanged legacy implementation.

## Permission acquisition

`CalendarGlanceProvider.enable()` never requests EventKit access. This is the restore/start seam used for persisted enabled intent: `.notDetermined` produces an enabled, idle status with capability `.permissionRequired` and health `.healthy`, because the prompt-free provider machinery is functioning normally while it waits for a contextual user action. It owns no observer, query, boundary, or prompt.

A contextual user action may call `requestFullAccess()`. Permission acquisition is explicit and separate from provider start; after a grant, the caller invokes `enable()` again to start or resume observation. Concurrent contextual calls share one request, and disable drains a request already in flight. Denied, restricted, required, and failed states are closed values and never retain external error text.

## Presentation policy

The surface should be absent when no relevant activity exists:

- Battery treats the first ordinary snapshot as a quiet baseline. Later ordinary changes are transient for 1.8 seconds through the broker's cancellable one-shot expiry. An unplugged battery at or below 20% is ambient until the condition changes or the provider is disabled. Enabling alone never creates a battery activity.
- Calendar queries the next non-all-day, non-cancelled event within the bounded look-ahead, but presents it only from ten minutes before its start through its end. A distant meeting creates no broker activity and owns only one suspended lead-time boundary. Lead, start, and end transitions each use a single successor one-shot.
- Timer submits timestamp-derived state once when activated. It retains only an expiry one-shot while presentation demand is hidden. `setPresentationDemand(.visible)` enables aligned second-level successor one-shots and broker refreshes; hidden, expiry, cancellation, and disable stop live updates immediately. Countdown replacement/cancellation and visibility demand share one FIFO mutation tail but use separate staleness revisions: a later demand may retire an obsolete demand boundary without suppressing a logically earlier queued replacement or cancellation. The brief does not justify a display link or subsecond animation, so none is used.
- Volume remains a transient 1.8-second event-driven acknowledgement.

The new battery and meeting-window initializers report validation through `BatteryPresentationPolicyError` and `CalendarPresentationWindowError`. They do not add cases to the pre-existing `GlanceConfigurationError`, preserving exhaustive switches in existing clients.

Calendar observation includes EventKit store changes, system clock changes, time-zone changes, and wake. These events re-query and converge the current presentation and its one-shot boundary; there is no idle polling. Its bounded relay coalesces equivalent pending triggers but never lets a store change weaken a pending clock, time-zone, or wake trigger, because system triggers must force both presentation and boundary replacement. Broker submissions and cancellations run through one cancellation-insensitive mutation tail, so an older noncooperative call cannot land after a newer broker intent. A current nil, distant, or failed-query result always enqueues a clear intent behind any older mutation, even when no presentation has yet been recorded in provider state. `ActivityBroker` performs ownership comparison and mutation within one synchronous actor-isolated operation. Its refined-protocol witnesses enter the actor once and delegate without an intervening suspension. Other event streams use newest-only bounded buffering, and provider generation/revision checks make late callbacks inert.

## Verification and remaining gaps

`EryloGlanceTests` deterministically covers prompt-free persisted restore, explicit permission requests, quiet battery and distant-calendar baselines, lead/start/end boundaries, clock/time-zone/wake convergence, system-dominant burst coalescing, reordered Calendar submit/cancel races against newer submissions, stale submit supersession by nil/distant/query-failure and disable outcomes, Calendar and Countdown last-reference cleanup, gated old-submit/new-provider publication in both drop and disable orderings, permission-denied/not-determined/restricted and source-start-failure takeover of an old visible meeting, public unleased replacement versus provider disable/deinitialization, refined-protocol ownership and conditional-cancel witnesses, runtime enable/submit/cancel through an original-shape external broker conformer, explicit-disable/deinit/replacement overlap, blocked-submit then queued Countdown replacement/cancellation plus visibility-demand ordering, visible timer progress and expiry, cancellation, repeated and overlapping lifecycle calls, duplicate-work prevention, cancellation-insensitive drain, reusable mutation capacity, and zero broker work from stale callbacks after disable. `EryloActivityTests` covers ownership capacity, pruning and reuse, record-generation binding, public submission/cancellation fencing, and expiry invalidation. The same provider drop and replacement probes run in debug and optimized harnesses. Debug and release builds run with warnings treated as errors through the publication evidence recorded on the pull request.

The package still does not connect Glance to settings, persisted provider factories, the activity surface's visibility feedback, or application termination. Real EventKit accounts and prompts, IOPowerSources delivery, CoreAudio device switching, macOS sleep/wake timing, wall-clock and time-zone notifications, and settled energy use still require a signed app bundle, real hardware, and Instruments. The second-level timer demand seam must be wired to actual broker/surface visibility before live progress is claimed in the app. Third-party brokers that need cross-instance Calendar/Countdown fencing must adopt `GlanceOwnershipActivityBroker`; the original two-method contract intentionally preserves its historical runtime semantics.
